# Alur Ticket Superagent di Pi

## Gambaran besar

**Ticket** adalah wadah pekerjaan yang bertahan lintas sesi Pi. Ticket, Mandate, Assignment, dan Report disimpan melalui Engine/SQLite; board Ticket menyimpan task agent, diskusi, checkpoint, proposal, dan keputusan owner. Gunakan `SA_STATE_DIR` yang **sama** untuk daemon dan Pi agar Ticket lintas sesi terlihat. Menutup Pi menghentikan lease kolaborasi; melanjutkannya perlu persetujuan `/collaborate` lagi.

```text
Source (prompt yang disetujui) → Trigger → Thread/Subscription
  → Eval + Policy → Decision → Ticket + Mandate
  → Assignment + PiExecutor → Report → Channel

Ticket → board → task → reviewer → checkpoint / hasil / handback / proposal
```

**Task board bukan Assignment Engine.** Hasil coding di board dan diff working tree **belum otomatis menjadi Report Assignment atau dikirim melalui Channel**. Follow-up yang disetujui owner masuk lagi sebagai Trigger di Thread Ticket, bukan sebagai Report langsung.

## Langkah demi langkah

1. **Buat Ticket:** `/ticket <tujuan>`. Setelah kamu menyetujui teksnya, prompt masuk sebagai Trigger lokal. Engine melakukan Eval/Policy dan Decision; bila diterima, ia membuat Ticket/Mandate dan Assignment. Investigator menghasilkan Report awal. `/tickets` menunjukkan Ticket yang dimiliki OS user ini di state directory yang sama, termasuk dari sesi Pi lain. `latestReport: "waiting"` berarti Report investigator telah tersimpan dan menunggu informasi lanjutan, **bukan** berarti task coding selesai.
2. **Task pertama:** extension membuat task awal dari tujuan Ticket. `/board <ticket-id> [page]` menampilkan task, pesan, proposal, dan progres dalam halaman yang mudah dibaca (default halaman terbaru, dengan judul dan status tiga task terbaru selalu terlihat). Pada Pi TUI, `/board` membuka viewer khusus yang menggantikan area editor selama dibuka, bukan popup atau widget bawah; snapshot diperbarui otomatis. Gunakan `←/→` untuk pindah halaman, `↑/↓` atau `PgUp/PgDn` untuk gulir, dan `Esc` kembali ke chat tanpa menghentikan collaboration. Setelah persetujuan `/collaborate`, viewer board terbuka otomatis. Legenda dan keterangan waktu board tersedia dalam bahasa Inggris. Pesan baru dan task yang benar-benar berstatus `done` mendapat notifikasi hijau di TUI selama sesi aktif; checkpoint bukan tanda selesai, dan riwayat lama tidak memunculkan notifikasi ulang. Task `open` dapat dikerjakan; `done` tidak diulang otomatis.
3. **Ikat repo:** `/workspace-bind <ticket-id> <path-absolut-root-repo> [go|rust|cpp]` meminta persetujuan untuk mengikat repo dengan profil bahasa eksplisit (default Go). Binding lama tetap Go-only. Sebelum izin file, reviewer hanya boleh melihat **nama file source tracked yang eligible untuk profil tersebut**, bukan isinya. Binding saja tidak membaca konten file melalui agent dan tidak mengeditnya.
4. **Jalankan discovery:** `/collaborate <ticket-id>` meminta persetujuan lease Pi dan agent lokal `reviewer`. Selama sesi aktif, Superagent meng-claim task siap dan menjalankan maksimal empat turn per lease. Checkpoint yang sengaja dipublikasikan agent terlihat selama bekerja dan tercatat di board; itu **bukan chain-of-thought privat**. `/pause-collaboration` atau menutup Pi menghentikan lease. Turn yang ambigu/telah selesai tidak diulang otomatis.
5. **Tinjau proposal:** `/proposal <ticket-id> <proposal-id>` menampilkan dialog Yes/No. Untuk proposal `files`, **Yes** menyetujui akses **baca saja** ke file Go asli yang tercantum; tidak otomatis memulai coding. **No** menolak. Periksa setiap path sebelum Yes: proposal tidak dapat disetujui sebagian. Untuk mengedit semua path yang telah disetujui, gunakan `/workspace-write-approve <ticket-id>` dan setujui dialog terpisah **sebelum** memulai turn coding. Jika scope terlalu luas dan belum ada edit, `/workspace-revoke <ticket-id>` mencabut izin lama; buat proposal baru dengan scope sempit. Grant dengan edit atau intent yang belum selesai tidak dapat dicabut otomatis.
6. **Lanjutkan pekerjaan:** jika task discovery sudah `done`, buat task baru dengan `/task <ticket-id> <pekerjaan spesifik>` dan setujui dialognya. Untuk coding gunakan `/task <ticket-id> --code [--profile=name] <pekerjaan spesifik>` setelah scope tulis disetujui; profil opsional dibaca dari template Pi milik owner, bukan agent baru. `/code-task` tetap alias profil `default`. Coder hanya punya tool baca/edit file yang disetujui dan tidak menjalankan shell/tes. Dengan `/collaborate` yang aktif, reviewer dapat mengambil task baru dan bekerja hanya dalam scope yang disetujui. Jika pekerjaan di luar scope, ia dapat mencatat **handback** dan proposal yang menunggu keputusan owner. Persetujuan proposal tidak memutar ulang task lama.
7. **Review edit:** `/workspace-files <ticket-id>` menunjukkan file yang diizinkan/diubah beserta mode izin; `/workspace-diff <ticket-id>` membuka viewer khusus TUI per file (`←/→` pindah file, `↑/↓` gulir, `Esc` kembali ke chat) yang menampilkan snapshot lengkap isi sebelum/sesudah edit yang dilakukan lewat Ticket, bukan patch hasil perhitungan. Jika edit terputus, operasi fail-closed; `/workspace-inspect <ticket-id> <path>` menunjukkan hash sebelum/sesudah dan apakah file cocok dengan salah satunya. Intent **tidak otomatis diselesaikan atau diputar ulang**: tinjau Git diff dan lakukan recovery manual. File Go yang disetujui **berubah langsung di working tree repo asli**, tanpa commit atau push otomatis. `/workspace-format <ticket-id>` meminta konfirmasi dan memeriksa `gofmt` via stdin **tanpa menulis repo**; ini bukan tes Go. Tidak ada test runner Go otomatis: **jangan klaim refactor aman atau lolos tes sebelum benar-benar diuji oleh owner secara terpisah**.
8. **Follow-up resmi:** `/ticket-followup <ticket-id> <teks>` meminta persetujuan untuk mengirim Trigger baru ke Thread Ticket yang sama. Subscription dapat meneruskannya sebagai Input ke Assignment/Executor dan menghasilkan Report baru. Ringkas hanya temuan/tes yang telah diverifikasi; diff dan percakapan board **tidak otomatis disalin** ke Report.

## Status contoh Ticket auto-order

Ticket `57b5132992f7b70031995aa4ff38eb08` sudah dibuat dan diikat ke `~/work/growin_autoorderservice`. Task **discovery** selesai; reviewer hanya melihat nama file dan mengusulkan 12 path. Proposal `231a169f-058f-4153-b293-23009e73dead` disetujui owner **sebelum** pemisahan mode izin diterapkan; grant lama tetap dapat dibaca tetapi tidak memperoleh hak edit pada implementasi baru. **Approval itu tidak menjalankan coding:** belum ada task coding baru, dan pemeriksaan Git terakhir belum menunjukkan perubahan file tracked oleh Superagent.

**Jangan jalankan task coding dengan grant 12-file itu.** Setelah restart daemon/Pi dengan versi baru, cek `/workspace-files <ticket-id>` lalu gunakan `/workspace-revoke <ticket-id>` ketika tidak ada turn aktif. Buat proposal `files` baru untuk path yang benar-benar perlu, review read-only, baru berikan izin edit secara terpisah. Fitur re-scope adalah revoke + grant baru, bukan mengubah subset grant lama. Tidak perlu membuat Ticket baru hanya untuk melihat board atau melanjutkan task pada Ticket yang sama.

## Batas keamanan dan kemampuan

- Pembatasan tool/path adalah **allowlist aplikasi, bukan sandbox OS**. Socket owner-only juga tidak membedakan dua proses milik OS user yang sama; dialog Pi tidak mengamankan request socket dari proses lain milik user tersebut.
- File `.env`, kredensial, konfigurasi, CI, dan file di luar path Go yang eligible tidak boleh diedit melalui tool workspace. Deteksi rahasia sederhana **bukan jaminan** bahwa file yang disetujui bebas rahasia. Konten file yang dibaca agent dapat dikirim ke provider Pi yang kamu konfigurasi.
- Tidak ada shell/test runner untuk reviewer, commit/push otomatis, orkestrasi coding multi-agent, atau semantic retrieval/memory proyek lama dalam alur ini. Eksekusi `go test` dapat menjalankan kode proyek dan mengakses resource OS/network; pemeriksaan `gofmt` saja tidak memberikan izin itu. Investigator Engine tetap memakai tool read-only miliknya sendiri.
- Repo target dapat punya state untracked milik pengguna (misalnya `.swarm/`); Superagent tidak boleh menghapus, reset, atau menimpanya. Jika file yang disetujui sudah berubah di luar Ticket, akses/edit harus berhenti, bukan overwrite.
