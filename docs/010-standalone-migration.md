# Standalone migration design

Audit (source and type-import closure):
- Preserve `src/core/*` (Engine, Tickets, Triggers, Threads, Mandates, Assignments), `src/app/store.ts`, store reads/schema 11, local trigger/intake and SHA-256 evidence storage, Policy gate, and domain tests.
- Migrate infrastructure: `policy.ts` imports a DSH subprocess utility only for a command-name constant; `store.ts` imports `migration.ts`, whose imports recursively include DSH session/context, prompts, notices, source adapters and typed KV imports (`github.ts`). Decouple these without changing schema 11 data. Retain schema 10 migration behavior where feasible.
- Replace DSH executor (`src/executor/dsh.ts`), plugin runtime (`src/app/runtime.ts`, `src/index.ts`), assessor and source plugin with explicit local Engine orchestration, Pi SDK sessions and an owner-only socket.
- Remove unused DSH/Cordis client UI, Github/Feishu execution integrations, plugin presets, deployment scripts and their tests/docs. Keep domain/store/local regression tests; add deterministic fake Pi adapter integration tests.

Architecture: owner-only CLI/socket -> local ingress -> Engine.receive -> Policy gate -> Engine.decide -> durable Store/Assignment -> Pi executor (restricted tools) -> validated Engine.report. SQLite Ticket is authoritative; Pi JSONL session is supplemental. Start/delivery/stop are queued after transaction commit; startup scans pending/running assignments and reconciles through Engine methods. No shell, file, network, extension discovery, or OS sandbox is offered to the investigator. Previous Ticket findings are injected on every turn. A durable turn marker prevents blind replay after an ambiguous crash; ambiguous turns fail closed for explicit retry rather than duplicate model calls.

Trade-offs: serial worker queue favors correctness and simpler crash semantics over throughput; SQLite synchronous transactions avoid concurrent state races. Tool allowlisting and a resource loader with no discovery favor security over extensibility; provider-side inference still sends submitted context to the configured model. Failed turns remain retryable via Engine rather than unsafe automatic replay. No lock-free structures or sub-millisecond target are required in this local, I/O-bound process. Risks: provider/network retries can repeat model inference without side effects; JSONL and SQLite cannot commit atomically; model output is untrusted and schema-validated. No OS-level process isolation is claimed.
